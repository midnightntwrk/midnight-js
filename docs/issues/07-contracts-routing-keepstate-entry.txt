TITLE: feat(contracts): protocol-version routing + dedicated keep-state entry (MJS-02)

CONTEXT
Architecture doc sections 3.2 (contracts component), 3.3 (injection flow),
4.1 (routing decision view) and 4.2 (keep-state sequence). The v9-native
entry's signatures and generics are UNTOUCHED (FR7) — keep-state is a separate
entry because 0.16-generated contract types cannot satisfy the v9-pinned
generics of the existing one.

SCOPE
- Per-operation version resolution via networkHeadVersion (memoised within the
  operation only; requires the provider member from ticket 08 — develop against
  a mock until 08 lands).
- Routing truth table (section 4.1 — TOTAL over shapes, adversarial input):
    co.v2-only            -> keep-state
    v3/ir, no co.v2       -> v9-native (default, untouched)
    both populated        -> v9-native + dual-key breadcrumb
    neither               -> typed unsupported-key-set error
  Provenance caveat A4 (section 4.1): co.v2-only assumes every v9-era deploy
  populates v3/ir (unconfirmed — asked with OQ13); until then the
  missing-config error names BOTH plausible causes and the path breadcrumb
  carries key-set shape + contract address (QA-7).
- submitKeepStateCallTx (dedicated entry): keepState bridge attaches as a TYPED
  OPTIONS FIELD of this entry, not the global providers object (section 3.3,
  point 1). Identity check usesSameLedgerInstance(ContractState) at the START
  OF EVERY INVOCATION, before any fetch/proving ->
  KeepStateLedgerInstanceMismatchError (section 3.3, point 2).
- SINGLE-SNAPSHOT invariant (section 3.2): exactly one queryRawContractState
  fetch; contracts decodes those bytes for routing + SEC-5, hands the IDENTICAL
  bytes to executeCall (closes the intra-operation TOCTOU).
- Compose Intent -> Transaction via existing zswap-utils (v9-native binding);
  prove V2 SELECTED BY KEY TAG (never hardcoded); pass retained key triples
  through the configured proofProvider (plumbing here; API shape = OQ12,
  section 3.2 proof-providers row).
- SEC-5 pre-proving check: local verifier key byte-matches fetched co.v2 slot
  (defence layer 3, section 6.2).
- Typed errors per the section 7 table (stable `code` discriminant on every
  class — dual npm scopes break instanceof): pre-fork head (D9), post-fork
  v8-artifact deploy, missing keepState option (exact snippet + both causes),
  stale-head via the QA-3 predicate (section 4.4: re-query head on submit
  rejection; error iff it differs from operation-start version, else re-throw
  with { cause }), unsupported key set, proof-version invariant.
- Breadcrumbs (section 6.2, defence layer 6): all four dispatch decision points
  emit debug-level loggerProvider breadcrumbs (selected version, path, source,
  raw int; path breadcrumb += key-set shape + contract address). Privacy
  constraint (layer 7): no key bytes, no decoded state, no payloads.
